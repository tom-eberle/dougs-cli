# The Dougs private API (as used by dougs-cli)

Dougs has no public API. Everything below was learned from the web app's JavaScript bundle
(`https://app.dougs.fr/app/main-*.js` and its `chunk-*.js` files) and confirmed with read-only
requests. It can change without notice — `dougs doctor` checks the shapes the CLI depends on.

Examples use the invented company `999999` and invented ids. Values are illustrative.

## Conventions

| | |
|---|---|
| Base URL | `https://app.dougs.fr` (override with `DOUGS_API_BASE`, tests only) |
| Auth | Cookie `auth_session=<value>` — the web app's session cookie |
| Headers | `Accept: application/json`; a non-empty `User-Agent` (generic library agents such as `Python-urllib` get **403**) |
| Errors | JSON `{"message": "...", "statusCode": 404}`; 401 = no/expired session; 403 can also mean "not allowed for this user" with a valid session |
| Money | EUR as JSON numbers (`48.5`); VAT rates as fractions (`0.2`) on operations and categories |
| Company scope | Most paths start with `/companies/{companyId}` |

The CLI's `dougs api <METHOD> <path>` sends any request with these conventions; `{company}` in the
path is replaced by the active company.

## Identity

### `GET /users/me`
The current user, including the companies they can access.

```jsonc
{
  "id": 4242,
  "email": "someone@example.test",
  "profile": { "fullName": "Alex Example", "...": "..." },
  "companyIds": [999999],
  "companies": [{ "id": 999999, "legalName": "Fictional Widgets SAS", "brandName": "Fictional Widgets", "...": "..." }],
  "company": { "id": 999999, "vatConfiguration": { "type": "standardMonthly" }, "...": "..." }
}
```

Also present in the bundle: `GET /users/{id}/companies`, `GET /users/me?refreshSession=true`.

## Operations

An **operation** is a bank line (or manual entry) with one or more **breakdowns** (accounting
lines: category, amount, VAT). `isCounterpart: true` breakdowns are the automatic bank side;
edits target the non-counterpart ("main") ones.

### `GET /companies/{c}/operations`

| Param | Meaning |
|---|---|
| `limit`, `offset` | Paging; the web app uses `limit=40` |
| `validated` | `true` (booked) or `false` (waiting for validation). **Required** by some endpoints |
| `needsAttention` | `false` for the normal lists |
| `q` | Free-text search (unreliable for wording substrings — filter locally) |
| `q-date` | `YYYY-MM` or `DD/MM/YYYY`. **Not a strict date filter**: a month query also returns many operations from other months. The CLI does not use it |
| `q-amount`, `q-isInbound`, `q-accountId` | Further server-side filters |
| `autogenerated=true` | Includes future/auto-generated entries (e.g. scheduled ones) |

Each list (`validated=true` / `false`) is returned **sorted by date, newest first** across pages,
which lets a client stop paging early. `GET …/operations/count-operations?validated=…` exists but
caps at 100.

Operation (fields the CLI relies on; the real object has ~70):

```jsonc
{
  "id": 10001, "companyId": 999999, "type": "bank",          // bank | expense | miscellaneous:manual | dispatch:ecommerce:salesChannel
  "date": "2026-08-15", "wording": "CB FICTIONAL ORBIT", "memo": null,
  "amount": 48, "isInbound": false, "validated": true, "deleted": false, "excluded": false,
  "transaction": { "accountId": 501, "currency": "EUR", "amount": -48, "originalAmount": null, "originalCurrency": null, "changeRate": 1 },
  "breakdowns": [{
    "id": 100011, "isCounterpart": false, "isInbound": false, "section": "main",
    "amount": 48, "categoryId": 77, "resolvedCategoryId": 77, "resolvedCategoryPath": [77],
    "categoryWording": "Logiciels", "categoryGroup": { "id": 2, "name": "Frais de fonctionnement" },
    "vatRate": 0.2, "vatAmount": 8, "vatAmountWithRecoverageRate": 8, "manualVatAmount": null,
    "isVatAmountManuallyModified": false, "amountExcludingTaxesWithRecoverageRate": 40,
    "associationData": { "vatExemptionReason": "exemption:outbound:outsideEuropeanUnion" },
    "associations": [{ "name": "vatExemptionReason", "slots": { "reason": { "...": "..." } } }]
  }],
  "sourceDocumentAttachments": [{
    "id": 700001, "isDeletable": true,
    "sourceDocument": { "id": 800001, "type": "vendorInvoice", "externalId": "<vendor-invoice-uuid>",
      "amount": 48, "date": null,
      "file": { "id": 900001, "name": "invoice.pdf", "mimeType": "application/pdf", "url": "/files/<uuid>/actions/download" } }
  }]
}
```

Notes: `amount` is always positive (direction is `isInbound`); uncategorized breakdowns have
`categoryId: -1` and **no associations**. A breakdown's `isInbound` can differ from its operation
(fees inside an e-commerce payout).

### `GET /companies/{c}/operations/{id}`
One operation, same shape.

### `POST /companies/{c}/operations/{id}` — update (also: validate)
Body: the **full operation**, with the edited breakdown replaced inside `breakdowns`, plus
`updatedBreakdown` set to that breakdown. The server reads the edit from `breakdowns`;
`updatedBreakdown` only flags which one changed. Sending only `updatedBreakdown` returns 200 and
changes nothing — always re-read to verify.

- **Category:** set `categoryId`, `resolvedCategoryId`, `resolvedCategoryPath: [id]`,
  `isManuallyCategorized: true` on the breakdown.
- **VAT amount** (what the web app's VAT field does): `vatAmount` and `manualVatAmount`.
- **VAT exemption — two passes.** (1) zero the VAT: `manualVatAmount: 0, vatAmount: 0,
  vatAmountWithRecoverageRate: 0, vatRate: null, isVatAmountManuallyModified: true,
  amountExcludingTaxesWithRecoverageRate: <amount>`. The response now offers a
  `vatExemptionReason` association. (2) set `associationData.vatExemptionReason` to
  `exemption:outbound:outsideEuropeanUnion` | `exemption:outbound:insideEuropeanUnion` |
  `exemption:outbound:noAccountingDocument`. Set the category first: uncategorized breakdowns
  have no associations.
- **Memo:** the full operation with `memo` changed. The web app sends no `updatedBreakdown`;
  dougs-cli sends the unchanged main breakdown, like the reference scripts — the server accepts
  both.
- **Validate:** the full operation with `validated: true` (no dedicated endpoint). The web app
  refuses to validate while the operation shows errors (`errors[]`, an uncategorized breakdown,
  breakdowns that don't add up, a required exemption reason missing); so does the CLI.
- **VAT recovery:** `vatAmountWithRecoverageRate` / `amountExcludingTaxesWithRecoverageRate` are
  computed by the server from the category's recovery rate (partially recoverable VAT). Read them
  for deductible VAT; don't send your own values when changing a VAT amount.
- **Locks:** operations with `manuallyLocked` or `lockedByDate` are not editable. An edit touching
  locked accounting lines fails with a 4xx and the header
  `X-Message-Code: accountingLine.lockedByDateWithAccountingNumber`. The web app then offers
  accountants (only) to retry with `?force=true`, which **unlocks the ledger**. dougs-cli never
  sends `force` and reports `LOCKED` instead.
- **Refunds:** breakdowns carry `isRefund`; a refund reverses VAT of the opposite flow (money back
  from a supplier reduces deductible VAT).

Related (seen in the bundle, unused): `GET …/operations/{id}/associations/vat-exemption-reasons`
(sales exemption choices), `GET …/operations/{id}/breakdowns/{b}/available-categories`,
`GET …/operations/{id}/actions/autocategorize-matching-operations`, `DELETE …/operations/{id}`.

### Documents
- **Attach:** `POST /companies/{c}/operations/{id}/source-document-attachments/actions/create-from-formdata`,
  `multipart/form-data`, field `file` (repeatable). Dougs shows the uploaded filename and
  classifies the document asynchronously (`type`: `unknown` → `vendorInvoice`).
- **Attach an existing document:** `POST …/operations/{id}/source-document-attachments` with a form-encoded body `sourceDocumentId=<id>`.
- **Detach:** `DELETE /companies/{c}/operations/{id}/source-document-attachments/{attachmentId}`.
- **Bind a vendor invoice:** `POST /companies/{c}/vendor-invoices/{id}/actions/attach-operations`
  `{ "operationIds": [...] }`.
- **Download:** `GET /files/{uuid}/actions/download` → `302` to a signed S3 URL. Follow it
  **without** the cookie.

### `GET /companies/{c}/vendor-invoices/{uuid}`
Dougs' own reading of a supplier invoice — cheaper and often better than parsing the PDF.

```jsonc
{
  "id": "<uuid>", "prefillStatus": "prefilled",            // or not_applicable, pending…
  "amount": 120, "vatAmount": 0, "currency": "EUR",
  "supplierName": "Fictional SaaS Inc", "supplierCountry": "US", "supplierVatNumber": null,
  "foreignSupplierChargedFrenchVat": false,
  "vatBreakdown": [{ "vatRate": 20, "netAmount": 120, "vatAmount": 24, "categoryCode": "AE", "exemptionReasonCode": "VATEX-EU-AE" }],
  "fileName": "invoice.pdf", "filePath": "/files/<uuid>/actions/download",
  "operations": [{ "id": 10001, "date": "2026-08-05", "amount": 120 }]
}
```

`categoryCode: "AE"` is the UNCL 5305 code for reverse charge; the top-level `vatAmount` is what
was invoiced (0 for reverse charge). Note `vatRate` here is a percentage.

## Reference data

### `GET /companies/{c}/categories?full=true`
All categories (~2,400, ~2.5 MB; the CLI caches it 24 h). Without `full=true` it returns only ids.

```jsonc
{
  "id": 77, "wording": "Logiciels", "hidden": false, "isAssignable": true, "isInbound": false,
  "parentId": null, "accountingNumber": 626100,               // number, string ("6461XX", "associateAccount") or null
  "resolvedAccountingNumbers": ["626100"],
  "group": { "id": 2, "name": "Frais de fonctionnement" },
  "vat": { "rate": 0.2, "isOptional": false, "isReversable": true }   // rate can also be a keyword, e.g. "fromEuCountries"
}
```

### `GET /companies/{c}/accounts`
Bank accounts: `id`, `accountName`, `bankName`, `currency`, `closed`, `hidden`,
`metadata.balance.balance` (live, native currency), `metadata.balanceUpdatedAt`. There is no
as-of-date parameter. `GET /companies/{c}/treasury-accounts` returns a lighter summary.

### `GET /companies/{c}/accounting-years`
`[{ "id", "openingDate", "closingDate", "closed", "isCurrent", ... }]`.

## VAT declarations

### `GET /companies/{c}/declarations/list-declarations?status=completed&limit=200&offset=0`
Light summaries. `status` is required: `completed`, `upcoming` or `ready_to_complete`. Fields:
`id`, `type` (e.g. `CA3-2026` for the monthly 3310-CA3), `label`, `periodStartDate`,
`periodEndDate`, `isFilled`, `dueDate`, `summaryAmount`, …

`GET /companies/{c}/declarations` (no parameters) returns every declaration with full payloads
(several MB); avoid it.

### `GET /companies/{c}/declarations/{id}`
One declaration with `form`: box code → value in **whole euros**. Filed CA3s carry the filed
figures. **Open months (`upcoming`, `ready_to_complete`) also carry a fully computed draft form**,
recomputed per period by Dougs; `dougs vat summary` shows it beside its own estimate. Summaries
also give `dueDate` and `isLate` (overdue and not filed). Several `completed` CA3s for one month
mean a corrective return; use the latest by `confirmedAt`. A draft's box 27 (credit to carry
forward) is provisional until the month is filed.

Box codes used by `dougs vat summary` (labels from `GET /declaration-templates/CA3-2026`):

| Box | Meaning |
|---|---|
| `A1` | Sales and services (taxable) |
| `A3` (`A3:01` EU, `A3:02` non-EU) | Services bought from suppliers not established in France (reverse charge) |
| `E1`, `E2`, `F2` | Exports, other non-taxable operations, intra-EU deliveries |
| `08`, `08:VAT` | 20 % base and tax (includes self-assessed reverse charge: `08:C` EU, `08:D` non-EU) |
| `9B`, `09` | 10 % and 5.5 % bases (`…:VAT` for the tax) |
| `16` | Total VAT due (gross) |
| `19` | Deductible VAT on fixed assets |
| `20` (`20:A` France, `20:B` EU reverse charge, `20:C` non-EU reverse charge) | Deductible VAT on other goods and services |
| `22` | Credit carried forward from the previous return |
| `23` | Total deductible VAT |
| `25` | VAT credit · `27` credit to carry forward · `26` refund requested |
| `28` | Net VAT due · `32` total to pay |

## Not yet supported

| Need | Why not in v0.1 |
|---|---|
| Regenerating a declaration (`POST …/declarations/{id}/actions/generate-preview`) | A write; the existing draft is read instead |
| Unlocking locked ledgers (`?force=true` on updates) | Accountant action with ledger consequences; done in the web app only |
| VAT assistant (`GET …/actions/vat-assistant`) | Shape is a UI wizard state; no stable data to expose |
| Operation history (`GET …/operations/{id}/changes`) | Returns 403 for regular users |
| Filing/confirming declarations (`…/declarations/{id}/actions/confirm`) | Out of scope: the CLI never files anything |
| Password / 2FA login (`POST /auth/api/login`, `/auth/api/mfa/*`) | Out of scope; use the browser session or `--with-token` |
| Sales invoices, e-commerce dispatch edits, cash register | Not part of the v0.1 workflows; reachable with `dougs api` |
| App-store revenue ventilation (EU / non-EU split) | Planned for v0.2 |
